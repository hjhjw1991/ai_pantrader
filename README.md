# 候潮

A 股盘面量化系统 · 本地优先 · 人在环上 · 闭环自校准

一台机器上跑完整条链路：采集 → 因子 → 策略 → 信号 → 台账对账 → 参数回写建议。
数据留在本地，不依赖任何付费数据源，不需要服务器。

> **红线：系统不会自动下单。** 下单在券商 App 手敲，回来在持仓页回填成交。
> 自动化要等券商权限到位 **且** paper 模式连续跑满一个季度并达标。前端里不存在下单能力，也没给它留配置口子。

## 一键安装

需要 **Node ≥ 22**（`node -v` 检查；没有就 `nvm install 22 && nvm use 22`，仓库根目录有 `.nvmrc` 给的是推荐版本）。

> 曾经上界也卡死（`>=22 <23`），因为 `better-sqlite3` v11 用 `prebuild-install`，预编译产物**按 Node ABI 分**，换大版本就装载失败。
> 升到 v13 之后这个前提没了：它是 N-API，产物按**平台**分（`darwin-arm64` / `linux-x64` / `win32-x64`…），同一份 `.node` 跨 Node 大版本加载。
> 实测同一份安装在 Node 22（ABI 127）与 Node 24（ABI 137）下各跑通 1136 个测试，并读通了 2.4 GB 的真实库。
>
> 仍然保留下界：代码按 Node 22 的语法与内置 API 写。
>
> 两层拦截：`.npmrc` 里的 `engine-strict=true` 让**任何 `pnpm` 入口**在版本过低时启动即失败（不再是一行 WARN 照跑）；
> `node scripts/setup.mjs --check` 会额外真装载一次 `.node`，把"版本号对但产物坏了"也探出来（从别的机器拷 `node_modules` 就会这样）。
> 万一还是漏到了运行时，网页的 503 会把 ABI 号翻成"换回 Node 几"的具体动作。

**环境体检**：`node scripts/doctor.mjs` 按你所在的平台列出每一项的现状、是否必需、缺了怎么补 —— 编译器（macOS Xcode CLT / Windows VS Build Tools / Linux build-essential）、磁盘余量、定时任务指向的 Node 还在不在。只读，不改任何东西。

```bash
git clone <仓库地址> pantrader
cd pantrader
node scripts/setup.mjs --start
```

这条命令会：检查环境 → 装依赖 → 建库跑迁移 → 灌证券清单与交易日历（打网络，1–3 分钟）→ 构建 → 启动网页 **http://localhost:3111**

Windows 一样这条命令，PowerShell 或 CMD 都行——脚本是纯 Node，没有 `.sh` / `.ps1` 两份实现。

### 其它开关

| 命令 | 用途 |
|---|---|
| `node scripts/doctor.mjs` | 环境体检：按平台列出缺什么、怎么补。**只读**，装依赖前就能跑 |
| `node scripts/setup.mjs --check` | 安装前的闸门：只看能不能往下装，**不改任何东西** |
| `node scripts/setup.mjs --no-data` | 跳过灌数据，不打网络。先看界面结构 |
| `node scripts/setup.mjs --dev` | 开发模式启动（热更新，比生产模式慢） |
| `node scripts/setup.mjs` | 装完就停，不启动 |

装完之后日常只用 `pnpm start`。

### 手动安装（想逐步看清每一步）

```bash
pnpm install            # 装依赖
pnpm run migrate        # 建库 + 跑迁移（数据库落在 ~/PanTraderData/）
pnpm run seed-strategies # 从 config/strategies/*.yaml.example 播种策略实文件
pnpm run bootstrap      # 灌证券清单 + 交易日历。可中断，重跑自动续拉
pnpm build              # 构建
pnpm start              # 启动 → http://localhost:3111
```

`seed-strategies` 不能省：**策略实文件不进 git**，仓库里只有 `.yaml.example` 模板。
原因是 `持仓:` 段的键名就是你自己的账户 id，那是个人数据，不该躺在发行源里。
这一步幂等 —— 实文件已存在就跳过，不会覆盖你改过的阈值。

`pnpm` 没装就 `npm i -g pnpm`。用 npm 也能跑，但仓库带 `pnpm-lock.yaml`，npm 会忽略锁文件里的确定版本。

## 装完先做三件事

**1. 建账户** → http://localhost:3111/positions 最下面

系统**不预置任何账户**。账户是你组织自己资金的方式，程序无权替你起名。

三个字段：`账户 id`（台账主键，建后别改）、`显示名`、`类型标签`（自由文本，仅用于分组展示）。

**2. 把策略里的账户键名改成你的 id** → `config/strategies/default.yaml` 的 `持仓:` 段

每账户的止损规则来自这一段，**按账户 id 作键**。键名对不上，那个账户就没有硬线规则——
持仓页会用一个红色面板点名"这些 YAML 键在 account 表里不存在"并列出真正拿到规则的账户，不会静默失效。

改法有两条：直接编辑那个文件，或用 http://localhost:3111/settings 的「策略原文编辑」——
后者保存前会做 schema 校验、给 diff、并把原文备份成 `~/PanTraderData/strategy-backups/<文件名>.YYYYMMDD-HHmmss`。

> 这个文件被 `.gitignore` 忽略（模板 `default.yaml.example` 才进 git），所以你改它不会让 `git status` 变脏。
> 代价是策略演化史不能用 `git diff` 看了 —— 载体换成上面那个备份目录，每次写回都留一份带时间戳的全文，
> 且随 `~/PanTraderData` 一起备份，不会被 `git clean` 或重装项目连带删掉。

**3. 看一眼数据健康** → http://localhost:3111/settings

数据源全是免费非官方接口，会掉线、会限频、会改字段。这一页摊开源健康明细与缺口清单：陈旧独立成一档，不会并进"正常"。

## 页面

只有一个主页 `/` 作战台：顶部一排是盘面环境（环境档位、情绪阶段、盘面温度、影子盘摘要，明细点开看）；主体左边是自选列表（今日候选 / 持仓 / 观察池分块，带迷你走势，点哪只看哪只，↑↓ 切换），右边是选中那只票的决策卡（动作、现价 / 触发 / 止损 / 目标、盈亏比、理由、技术面提示、下一步），或勾选几只（最多 4 只，`c` 勾选、`v` 切换）后的并排对比表，下面是交互式 K 线。左侧导航可折叠成图标栏（`[` 键），顶栏是快照时点、缺口徽标与通知铃。其余功能都是从右侧滑出的抽屉，数字键直达、Esc 关闭，地址可刷新可收藏：

| 键 | 路径 | 抽屉 |
|---|---|---|
| 1 | `/positions` | 我的股票：持仓、盈亏、止损距离、成交回填、**账户管理**；观察池 |
| 2 | `/shadow` | 影子盘：各组合成绩、毕业进度、待批切换、回滚 |
| 3 | `/market` | 盘面：涨停池聚合、连板梯队、板块涨幅、龙虎榜 |
| 4 | `/ledger` | 复盘与回测：预测台账与对账、胜率、参数回写建议；回测与 walk-forward |
| 5 | `/settings` | 数据源健康、缺口、调度状态、**策略管理**、参数面板、导入导出 |

页面每 60 秒自刷，另有 SSE 推送——档位切换 / 新增买入候选 / 硬线破位会弹桌面通知，例行数据刷新不弹。

## 数据采集

**只要跑起这个系统，采集就自动开始。** 跨平台进程内调度，不依赖 launchd / cron / 计划任务。

| 时间（上海） | Job | 内容 | 跨天可回补 |
|---|---|---|---|
| 08:50 | `selfcheck` | 缺口扫描 + 覆盖率 | ✅ |
| 09:00 | `preopen` | 同步交易日历 | ✅ |
| 09:15 | `plan` | 盘前作战计划：跑策略，推当天候选 | ❌ |
| 09:35–11:30 / 13:00–14:55 每 5 分钟 | `intraday` | 全市场快照 + 关注池分钟线 | ❌ |
| 15:05 | `close` | 收盘快照 + 涨停池 | ❌ |
| 18:40 | `post` | 龙虎榜 + 营业部席位 | ✅ |
| 22:00 | `night` | 全量日线 + 缺口回补 + 龙虎榜标签重拉 + 台账对账 | ✅ |

"跨天可回补"那一列是真实约束，不是标注习惯：**盘中快照是过去某一刻的现场，源上没有历史接口，缺一天就永久缺一天。** 所以漏采的时点如实记 `missed`，不记成成功——那等于伪造覆盖率。

两套调度可以同时装着，不会重复采集：进程内调度器和 OS 级定时任务（launchd / schtasks）
共用 `job_run` 表，主键 `(date, job, slot)` 谁先抢到谁执行，另一边直接放手。
所以"网页开着"和"装了开机任务"叠加不会让全市场快照被拉两遍。

> 这里踩过一次：`scripts/job.ts` 早先直接执行、不写 `job_run`，于是 OS 任务对调度器完全隐形。
> 实测 2026-08-21，launchd 跑完 `post`/`night` 之后网页一启动，调度器看表里没记录又整个跑了一遍。

想不开网页也采集：

```bash
pnpm run daemon          # 独立守护进程，带 PID 锁，不会起两个
```

装成开机级任务（可选）：

```bash
pnpm run install-launchd    # macOS
pnpm run install-schtasks   # Windows
```

### 唤醒补偿

系统重新活过来时（进程重启，或机器休眠后醒来）先问一句"上次干活是什么时候、漏了什么"：

- 回收卡在 `running` 的时点（休眠打断进程会留下这种残留，不回收就永不重跑也永不记 missed）
- 先同步交易日历，**再**判断漏了哪些交易日——日历是从指数历史 K 线推出来的，永远不含未来日期，不先同步就查不到沉睡期间任何一天
- 可回补的数据跑一次 `night` 做结构性覆盖（拉 1023 根日线 + 刷近 30 个交易日龙虎榜），不逐日重放
- 不可回补的时点如实记 `missed`

判据是"有交易日的可回补数据没落地"，不是"沉睡超过 N 小时"。后者会同时犯两种错：周末关机 60 小时其实一天都没漏，而周四到周五只隔 10 小时却漏掉了整个周五。

## 策略

策略是文件，不是数据库行：

```
config/strategies/<id>.yaml           可编辑的真相源，可增可删。**不进 git**
config/strategies/<id>.yaml.example   去个人化模板，进 git，供 seed-strategies 播种
config/strategies/ACTIVE              单行文本，当前生效的是哪个
```

实文件不进 git 是因为 `持仓:` 段的键名是你自己的账户 id。历史版本靠
`~/PanTraderData/strategy-backups/<文件名>.YYYYMMDD-HHmmss` 留存：每次写回（含面板改一个数）
都先备份，同一秒内连续保存加 `-2` 后缀，不做自动清理。

**YAML 是参数的唯一真相源。** 参数面板只是它的投影，不存第二份状态。面板改一个数字 = 在原文上替换一个纯量，注释与排版一个字节不动——那些注释记着每个阈值的由来，比面板改参的便利更值钱。

在 `/settings` 的「策略」面板里新增 / 切换 / 删除。新增是**复制现有策略的原文**（含全部注释），只改 `id:` 那一行；不是生成空模板，那会让你从"不知道这些数该是多少"开始。

跑出第一条预测时，策略原文会自动快照进 `strategy` 表（幂等，只留第一份）。这是删除能安全存在的前提：`prediction.strategy_id` 是台账归因键，快照在，文件就可以随便删，历史结论仍解释得清。

## 数据位置

```
~/PanTraderData/
```

```bash
pnpm db:export                      # VACUUM 一致性快照 + meta + sha256

pnpm db:import <f.ptbak> merge newer
```

## 常用命令

| 命令 | 用途 |
|---|---|
| `pnpm start` / `pnpm dev` | 启动网页（生产 / 开发） |
| `pnpm run daemon` | 独立采集守护进程 |
| `pnpm run job <name>` | 手动跑一个 job：`selfcheck` `preopen` `plan` `intraday` `close` `post` `night` |
| `pnpm run parity [天数]` | v1↔v2 引擎对照：真实因子跑最近 N 个交易日，逐字段比信号卡。不一致即退出码非 0 |
| `pnpm test` | 单元测试（**不打网络**） |
| `pnpm test:watch` | 单元测试，watch 模式 |
| `pnpm test:live` | 打真实接口的 smoke 测试 |
| `pnpm run migrate` | 跑迁移 |
| `pnpm run seed-strategies` | 从 `*.yaml.example` 播种策略实文件（幂等，不覆盖已有） |
| `pnpm env:doctor` | 环境体检（只读）：Node/工具链/磁盘/定时任务 |
| `pnpm env:setup --check` | 安装闸门（只读）。不带参数则真装：依赖 → 建库 → 灌数据 → 构建。首次部署见[一键安装](#一键安装)，那里用 `node scripts/setup.mjs`，因为那时 pnpm 和依赖都可能还没就位 |

> `import` / `setup` / `doctor` 是 pnpm 的内置命令，会**劫持**同名 script：敲下去跑的是 pnpm 自己那个，
> **退出码还是 0**，看着像通过了，其实我们的脚本一次都没执行 —— 静默假通过，最难发现的那种。
> 所以带前缀改名：`db:import` / `env:setup` / `env:doctor`。
> `db:export` 是跟着 `db:import` 对称（`export` 不是 pnpm 命令，敲错会直接报命令不存在，不会骗人）。
> `tests/package-scripts.test.ts` 钉住了这条，新加 script 时会自动查。

## 架构约束

这几条是硬约束，CI 里有断言守着，改动前先读：

- **`lib/data/` 是唯一允许发网络请求的目录**（唯一例外：advisor 传输层，已单独标注）
- **因子层与策略层不许碰数据库、不许读系统时间**。数据只能从 `PointInTimeView` 进来，"现在"只能是 `view.asOf`——否则回测会偷看未来，而看不出来
- **采集失败永不静默返回空**。必须抛错或记 `data_gap`。空响应体是限流的典型表现，不是"今天没数据"
- **时间戳一律上海挂钟时间**，毫秒精度（`source_health` 的主键需要）
- **台账只追加不改写**。同 id 同内容视为重复投递，同 id 不同内容直接报错

## 已知限制

- **少数北交所代码没有复权因子**：新浪不提供"定向转让"类代码的 `hfq.js`（实测 5,888 只里 3 只稳定 404：810011/810013/810014）。这些票的复权价按因子 1.0 处理 —— 有分红的会偏差，技术指标须知情。缺口表里留着一条不可回补的 `adj_factor:unsupported` 记着这件事
- **复权只认新浪一家**：东财与新浪的后复权算法不是同一套（浦发实测：1999 年吻合、2005 年差 2.5%、2026 年差 61%，比值随时间漂移 = 涨跌幅本身就不同）。库里的日线是新浪的，所以因子也只能用新浪的，周/月线则由复权日线**本地聚合**而来。混用两家会让日线与周线 MACD 跑在两条序列上，且不报错
- **ST 状态从 2026-08-04 起才有**：库里的 ST 区间是从证券简称观测出来的，而观测从系统上线那天开始 —— 328 只 ST 票的区间**全部**从这一天起算。更早的日期"没看到 ST"只代表没看见，ST 判据如实返回未判定，不会让回测放心买进一只当时正戴帽的票
- **减持计划只能做实盘，做不了深回测**：东财 datacenter 没有"减持计划"报表（它那张 `RPT_SHARE_HOLDER_INCREASE` 是已实施的事后披露，没有任何未来日期），只能走"东财公告列表按标题筛预披露 → 同花顺 F10 模板句解析"两段式。同花顺每只票只留最近约 2 条计划，所以这张表从 2026-09-23 接入起往前攒，更早的日期返回未观测
- **北向资金只剩活跃度，没有方向**：2024-08-16 起交易所停止披露北向净买额，之后能拿到的只有成交额与十大成交股。「北向活跃度」「北向关注」两个因子只说明外资忙不忙、看不看某只票，不说明在买还是在卖，所以只上卡片、不进决策。南向净买额仍在披露，一并记录
- **两融与互联互通只能看到评估日前一天**：两融 T+1 开盘前才发布，港交所收盘后才发当日成交，所以 PIT 视图对这两类数据只给严格早于评估日的行。两融个股回补了两年（2024-09 起），更早的日期「个股融资」返回无数据
- **资金面因子暂不参与决策**：两融情绪、个股融资、北向活跃度、北向关注、股东增减持目前只产出读数，阈值是先拍的，等滚动分位学出来再接进档位与否决
- **情绪周期原料由日线重建**：晋级率、涨停溢价、高度板溢价、炸板溢价、日线炸板率、涨跌中位数存在 `sentiment_daily` 派生表里（2022-05 起，即交易日历的起点），每晚日线入库后重建。涨停判定对过东财涨停池：31 天里 17 天逐只一致，其余每天差 1~2 家（多出的是东财池本身漏记的票）。两处口径局限：日线看不到"开板又回封"，所以炸板率是下界；ST 历史 2026-08-04 才开始观测，此前的 ST 涨停排除不掉，那段的涨停类统计略偏高
- **涨跌停阈值随规则变更分段**：创业板 2020-08-24 注册制改革前按 10%（ST 5%）；主板 ST 自 2026-07-06 起由 5% 放宽为 10%。另按精确涨停价（前收 × 限幅，四舍五入到分）兜底，否则 2 元左右的低价股涨停会被漏判
- **技术结构因子的口径**：日线 / 周线 MACD、ATR、结构位、M 顶 W 底都算在后复权价上，展示与定价用的数值再除以当日复权因子换回原始价（等同券商 App 的前复权），金叉死叉与拐点位置不受影响。周线只用已完成的周，本周不计，所以周线信号最多滞后一周。拐点左右各看 3 根，最后 3 根永远不是拐点，结构位与形态天然滞后 3 根。M 顶 W 底的默认参数（间隔 ≥10 根、颈线深 ≥6%、破颈 10 根内有效）是先定的，等影子盘攒够样本再校准
- **估值筛是粗筛，而且只有半边**：PE 在申万一级行业内排进最贵的 5%、并且是同行中位的 2 倍以上才否决（同行不足 10 家时退回全市场）。两个条件缺一不可 —— 只看分位会把工商银行（PE 8.27，银行业 0.95 分位，同行中位 5.2）当成估值畸高。估值只有 2026-09-23 起的当日快照，更早的日期这道筛是未判定；业绩（营收 / 净利润）那半边仍缺数据源，所以这道筛永远标"部分判定"
- **结构位定价是一套可选策略，不是默认**：v2 评估器槽位「结构位定价」在 baseline 筛完的候选上补目标价（优先取前高；前高已在触发价下方或上方无前高时用触发价 + 3 × ATR）与盈亏比，盈亏比低于 1.5 的不进候选。在 YAML 的 `槽位: { 评估器: { 用: 结构位定价 } }` 里启用。最近 60 个交易日：baseline 162 只候选，结构位定价保留 94 只，盈亏比中位 2.3。账户没配止损时盈亏比算不出来，保留但排最后
- **五段状态机是一套可选择时器**：七项情绪分位等权合成综合热度，做 5 日平滑后再相对自身 250 日历史取分位，喂给状态机判冰点 / 启动 / 发酵 / 高潮 / 退潮（高潮、冰点带 0.1 的滞回带宽，"明显变化"的幅度取热度变化标准差的一半）。默认映射：冰点中性、启动与发酵进攻、高潮中性、退潮防守；防守触发成立时阶段推不翻。在 `槽位: { 择时器: { 用: 五段状态机 } }` 里启用。需要约 370 个交易日的情绪历史，2023-11 之前判不出阶段。样本内检验（689 天，次日涨停溢价）：退潮日显著偏低（−0.45 个百分点，t = −2.4），高潮日显著偏高（+0.49，t = 2.1），其余三段与平均无差别 —— 高潮日次日仍有溢价这一点与"高潮不追"的默认映射相反，留给影子盘用真实候选的战绩裁决
- **影子盘与正式台账分开记、分开算**：每天 09:15 出正式计划后，9 套槽位组合（baseline、结构位定价、五段状态机、五段+结构位、五段高潮进攻+结构位、只做启动发酵+结构位，以及换上申万主线的三套）用同一份输入各出一批买入候选，记进 `shadow_pred`；夜里按止损 / 目标价模拟离场结算（次日够到触发价才成交、T+1、跳空按开盘、同日两者都碰按止损、一字跌停顺延、第 5 天收盘期满），扣双边滑点与费率。正式台账仍是"持有 5 天看收盘"，两本账的胜率不能直接比。影子盘只评估新开仓，不看持仓
- **影子盘的回放样本只排座次、不算毕业**：`pnpm shadow:replay [起始日] [截止日]` 把各变体从 2023-11-22 起逐日回放（可中断续跑）。回放是在已知结局的行情上跑已调好的参数，只用来发现明显不行的组合；毕业只看实盘影子样本。冷启动结果（690 天，扣约 0.66% 双边成本后的每笔净收益）：baseline −0.63%、五段 −0.55%、结构位 −0.59%、五段+结构位 −0.27%（对 baseline t = 1.3）、五段高潮进攻+结构位 −0.24%（t = 1.4）、只做启动发酵+结构位 +0.13%（t = 2.1，575 笔）。最后这套是**看了分阶段结果才挑出来的**（五段+结构位在启动期 +0.40%/笔、冰点期 −0.67%/笔），t 过 2 不作数，只能靠实盘影子检验
- **主线可以不靠写死的必查链**：baseline 的主线识别是「板块榜前几名 + 写死的四条必查链（半导体全链 / 军工 / 电网 / 资源）」，它保留着当对照组。新的主线识别器「申万聚集」不预设任何名单：按申万一级行业把当天的涨停股聚起来，涨停家数 ≥ 3 的行业按家数、最高连板、涨停占比取前 3；全市场最高板（≥ 3 板）所在的行业家数不够也算 —— 必查链想防的「板块均值掩盖龙头」漏扫，改由「那里有没有高度龙头」来判。它组成三套新组合进影子盘，赢了按毕业流程换上去。冷启动回放（690 天）里三套都不如对应的必查链版本：申万主线 −1.02%/笔（baseline −0.63%，t = −1.4）、申万主线+五段+结构位 −1.05%、申万主线+只做启动发酵+结构位 −0.84%，差异都不显著。注意回放偏向必查链：那四条链是站在今天挑出来的、恰好是这两年的主线，事后看当然准；真正的检验只能靠实盘影子。在 `槽位: { 主线识别器: { 用: 申万聚集 } }` 里可直接启用
- **影子盘毕业与切换**：每晚结算后比一次。挑战者要在与**在任组合**（当前正式策略用的那套，第一次切换前是 baseline）共同结清的实盘交易日上，攒够 ≥ 30 笔已结算、≥ 20 个交易日，期望更高且 Welch t ≥ 2，最大回撤不更深，才算毕业；槽实现升过版本的旧样本不算。过线的只取 t 最高的一个：前 2 次推通知等人批，之后自动切换。切换 = 改写策略 YAML 的 `槽位:` 段并升 patch 版本号，明天盘前计划起生效，`strategy_switch` 表记证据与经过。`pnpm shadow:switch` 看毕业进度与历史，`approve <id>` / `reject <id>` 批或否，`rollback` 一键回滚（版本号照样往前升；回滚后自动切换暂停，人重新批 2 次才恢复）。被否决或回滚的组合要再攒 20 个交易日新样本才重新参评；等批期间策略文件被手改过，提案作废，不覆盖人的改动。正式引擎因此换成了 v2：YAML 没写 `槽位:` 时跑 baseline，与 v1 逐字段一致
- **组合随时可加、可换**：`pnpm shadow:switch add <id> <名称> '<槽位JSON>'` 登记新组合，次日盘前起出信号；`retire <id>` 退役（样本保留）。id 一经登记不能改也不能复用 —— 要调参数就新开一个 id，旧的退役。baseline 与在任组合不能退役
- **没有盘中快照的日子用日线重建截面**：涨停池与板块榜只从 2026-08 起有真快照，之前的日子（回放、回测）用日线 + 申万三级历史归属重建代理：`zt_proxy`（收盘封在涨停价、连板数按日线数）与 `sector_rank_proxy`（行业成分股等权涨幅，成分 < 5 只的行业不上榜）。只在那天没有真快照时才用；真涨停池在、真板块榜缺的那天，涨停股的板块名也换成申万，保证两边是同一套名字。代理里没有封单额与开板次数（NaN，不是 0），主线置信度 ×0.75、龙头温度计标「未知是否开过板」
- **估值没有历史**：东财只给此刻的 PE/PB，没有历史接口。`valuation_daily` 从 2026-09-23 接入那天起往前攒，之前一片空白且永远补不回来。回测跑到更早的日期时估值类判据如实返回"无数据"，**不拿今天的 PE 回刷** —— 那是未来函数，而且偏向"今天看着便宜"的票。好在「PE 市场分位对比平均」要的是**横截面**分位（今天这只 vs 今天全市场），一天的快照就够算
- **行业归属早于 2021-12-13 一律返回 null**：74.6% 的票 `beginningdate` 压在 2021 版基期，在那之前申万这套分类根本不存在。返回 null 的意思是"不知道"，**不是"不在主线上"** —— 依赖行业的判据必须把它当未判定，不能当否决
- **周/月线只有走完的**：本周未收盘的那根不入库。写了会被明天的数据覆盖，回测重放到周二却读到含周五收盘的那根 —— 不越界读数据，而是让历史数据本身随时间改变
- **引擎不接账户资金，这是设计决定不是待办**：`StrategyEngineInput` 里刻意没有总资产/现金，也不打算加 —— 引擎只出比例，换算成金额由人来做。这条边界同时兜住了"系统不会自动下单"那条红线：一个算不出下单金额的引擎，没法被顺手接到自动交易上。代价是新开仓预算按目标仓位全额给、不扣已有持仓，信号卡会明确点出来要人工核对
- **组合风控另两条限额算不出来**：行业分类与核心卫星标记目前没有输入源。引擎会把它们列进信号卡的"未判定条件"，**不会当成通过悄悄放过**
- **回测只测得到三路候选来源里的一路**：代码→行业 映射没有历史版本，灌进回放就是未来函数；不灌则「主线领涨」「量价」两路自动关闭，只剩涨停池。回测报告会与数据覆盖率并列报出"真出过候选的天数"
- **涨停池历史短且不可回补**：它是当日现场快照，所以台账样本只能往前攒
- **两个 advisor 传输层未对真实端点验证**
- **macOS 合盖休眠拦不住**：`caffeinate` 无法阻止 clamshell sleep。要盘中数据完整就得开着盖
- 少数证券取不到实时快照（长期停牌 / 部分北交所），全市场覆盖率约 99.9%
